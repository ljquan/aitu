## Context

`ReferenceImageUpload` 已在自身上传占位区域处理 `dragenter`、`dragover`、`dragleave` 和 `drop`，并通过 `handleFiles` 完成校验、压缩、素材库写入和参考图状态更新。`AIInputBar` 也已有 `importLocalImages`，供文件选择与剪贴板粘贴共用。

新增能力的主要问题不是下游生成协议，而是扩大拖放命中区域时如何避免与画布拖动、文本拖放和浏览器默认打开文件行为冲突。

## Goals / Non-Goals

- Goals:
  - 整个 AI 图片生成弹窗接收本地图片文件拖放
  - 整个底部 AI 输入栏接收本地图片文件拖放
  - 两个入口均复用既有图片处理和参考图提交流程
  - 有效拖放期间提供稳定、不改变布局的视觉反馈
  - 不干扰画布、文本和其他非文件拖动
- Non-Goals:
  - 不解析从网页拖入的图片 URL 或 HTML
  - 不将画布中的图片元素通过 HTML5 拖放转换为参考图
  - 不扩展视频、音频或任意文件上传
  - 不改变参考图数量、压缩阈值、文件大小限制或后端协议

## Decisions

### Decision: 只在拖放包含图片文件时接管事件

拖放入口检查 `DataTransfer.types` 是否包含 `Files`，并在实际 `drop` 时从 `DataTransfer.files` 过滤 `image/*`。只有候选本地文件拖放才调用 `preventDefault` 并进入视觉激活状态。

这样可以保留 textarea 文本拖放、画布元素交互和其他浏览器行为。非图片文件进入现有校验链路后按统一规则提示或忽略，不新增第二套校验。

### Decision: 复用现有导入函数，不复制文件处理逻辑

- `AIInputBar` 的 drop handler 调用现有 `importLocalImages`
- AI 图片生成弹窗通过受控回调或轻量共享接口调用 `ReferenceImageUpload` 的现有 `handleFiles`
- 原上传占位区域继续工作，但父级接管后必须通过事件传播控制保证一次拖放只导入一次

若当前组件边界无法让父级安全复用 `handleFiles`，实现时优先抽取小型本地图片导入 helper/hook；不把完整上传组件状态提升到弹窗。

### Decision: 拖放反馈采用覆盖状态，不改变布局

输入栏和弹窗根节点增加拖放激活 class，通过边框、背景或局部遮罩表达可放置状态。反馈层不得阻挡已有控件，也不得使容器尺寸变化。

### Decision: 明确禁用与容量边界

- 生成中或入口禁用时不接收拖放
- 参考图已达到模型或组件数量上限时沿用现有数量提示
- 多文件拖入沿用当前顺序，并只接收剩余容量允许的图片

## Risks / Trade-offs

- 父级与现有上传占位区域都监听 drop，可能重复导入。通过统一入口或在子级已处理时停止传播并补测试规避。
- `dragenter` / `dragleave` 会在子元素之间频繁触发，可能造成高亮闪烁。使用 drag depth 计数或基于 `relatedTarget` 的边界判断稳定状态。
- 全局阻止默认行为会影响画布和文本交互。监听器必须限定在弹窗或输入栏容器内，并先确认本地文件拖放类型。
- `DataTransfer.items` 在不同浏览器实现不一致。候选判断使用 `types`，最终数据以 `files` 为准，并用组件测试覆盖缺省字段。

## Migration Plan

该能力只新增前端交互，不涉及持久化结构或接口迁移。若出现回归，可移除父级拖放监听和激活样式，原按钮上传、素材库、粘贴与小区域拖放仍可继续使用。

## Open Questions

- 无。当前范围固定为本地图片文件，不包含网页 URL 或画布元素拖入。
