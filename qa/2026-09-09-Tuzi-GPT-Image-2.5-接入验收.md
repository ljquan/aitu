# Tuzi GPT Image 2.5 接入验收

## 前置条件

- 使用 OpenTu 局域网开发地址或已部署站点。
- 配置 Tuzi Provider 地址。
- 配置完整格式的 `sk-...` Key。
- Provider 账户已具备对应图片模型渠道和余额。

## 功能验收

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 打开模型选择器 | 可看到 `gpt-image-2.5-1k`、`gpt-image-2.5`、`gpt-image-2.5-vip` |
| 2 | 选择任一模型并生成 `1:1` | 请求尺寸为 `1024x1024`，生成成功 |
| 3 | 选择任一模型并生成 `2:3` | 请求尺寸为 `1024x1536`，生成成功 |
| 4 | 选择任一模型并生成 `3:2` | 请求尺寸为 `1536x1024`，生成成功 |
| 5 | 选择 `3:4`、`4:5` 或 `9:16` | 自动映射到 `1024x1536`，不发送非法尺寸 |
| 6 | 选择 `4:3`、`5:4` 或 `16:9` | 自动映射到 `1536x1024`，不发送非法尺寸 |
| 7 | 手动输入 `2048x2048` 等其他尺寸 | 参数被过滤或回退为自动，不向 Tuzi 发送该尺寸 |
| 8 | 在公网和局域网站点分别生成 | 两端均沿用现有 Provider 配置和价格，不依赖额外 Key/数据库同步 |

## 鉴权与异常验收

- 使用完整 `sk-` Key 请求时，不应被 OpenTu 改写为无前缀 Key。
- Key 无效时显示 Tuzi 原始鉴权错误，不应误报为尺寸错误。
- 上游渠道不可用时显示 Provider 的渠道错误，不应将其归因于模型未注册。
- 生成失败卡片中的重试操作应复用原模型、比例和尺寸参数。
